# Shell Emulator

Эмулятор командной оболочки UNIX-подобной ОС на Python. Консольная программа,
которая имитирует работу в терминале: показывает приглашение, принимает
команды, выполняет их и умеет проигрывать команды из скрипта.

> Проект, **вариант 9**. Разрабатывается по этапам, результат каждого
> этапа сохранён отдельным коммитом.

# Этап 1. REPL

## Цель

Сделать минимальный прототип: большинство команд пока заглушки, но диалог
с пользователем уже работает.

## Что реализовано

| Требование | Как выполнено |
|------------|---------------|
| Консольный интерфейс (CLI) | программа запускается в терминале |
| Приглашение с именем VFS | `myvfs>` (имя задаётся константой `VFS_NAME`) |
| Парсер ввода | строка делится по пробелам на команду и аргументы |
| Заглушки `ls`, `cd` | печатают своё имя и список аргументов |
| Команда `exit` | завершает работу эмулятора |

## Как это работает

Программа повторяет цикл **ввод → разбор → выполнение → вывод**, пока
пользователь не введёт `exit`:

```
ввод строки  →  parse_line()  →  execute_command()  →  вывод результата
     ↑                                                        │
     └────────────────────────────────────────────────────────┘
```

Пример разбора: `ls -l папка1 папка2` → команда `ls`, аргументы `['-l', 'папка1', 'папка2']`.

## Запуск

```
python src/main.py
```

## Пример работы

```
myvfs> ls
ls: аргументы: []
myvfs> ls -l папка1 папка2
ls: аргументы: ['-l', 'папка1', 'папка2']
myvfs> cd папка1
cd: аргументы: ['папка1']
myvfs> foo
foo: команда не найдена
myvfs> exit
Выход из эмулятора
```

## Обработка ошибок и особых случаев

| Ситуация | Что делает программа |
|----------|----------------------|
| Неизвестная команда (`foo`) | выводит `foo: команда не найдена` и ждёт следующий ввод |
| Пустая строка | ничего не делает, снова показывает приглашение |
| Конец ввода (Ctrl+Z, Enter в Windows / Ctrl+D) | спокойно завершает работу |

# Этап 2. Конфигурация

## Цель

Сделать эмулятор настраиваемым: принимать параметры при запуске и выполнять
команды из стартового скрипта.

## Что реализовано

| Требование | Как выполнено |
|------------|---------------|
| Параметры командной строки | `--vfs-path` и `--script` (модуль `argparse`) |
| Отладочный вывод параметров | при запуске печатаются все заданные значения |
| Стартовый скрипт | команды читаются из файла построчно |
| Комментарии в скрипте | всё после `#` игнорируется |
| Диалог при выполнении скрипта | на экран выводится и ввод (`myvfs> команда`), и результат |
| Сообщение об ошибке | неизвестная команда в скрипте и отсутствующий файл скрипта |
| Скрипты реальной ОС | три `.bat`-файла в `scripts/` |

## Параметры запуска

| Параметр | Значение | Обязательный |
|----------|----------|:------------:|
| `--vfs-path` | путь к физическому расположению VFS | нет |
| `--script` | путь к стартовому скрипту | нет |

> Сейчас путь к VFS только запоминается и выводится. Чтение VFS появится на Этапе 3.

Примеры запуска:

```
python src/main.py
python src/main.py --vfs-path vfs/test.zip
python src/main.py --script scripts/start_ok.txt
python src/main.py --vfs-path vfs/test.zip --script scripts/start_ok.txt
```

## Формат стартового скрипта

Обычный текстовый файл, одна команда на строку:

```
# комментарий на отдельной строке
ls
ls -l папка1 папка2
cd папка1   # комментарий в конце строки
exit
```

- Пустые строки и комментарии пропускаются.
- Если встретилась ошибочная команда, выводится сообщение с именем файла и
  номером строки, а выполнение скрипта продолжается.
- Если скрипт закончился без `exit`, эмулятор переходит в интерактивный режим.

## Устройство программы

| Функция | Что делает |
|---------|------------|
| `parse_args()` | читает параметры командной строки |
| `parse_line()` | делит строку на команду и аргументы |
| `execute_command()` | выполняет одну команду, возвращает `ok`, `error` или `exit` |
| `run_script()` | читает скрипт, убирает комментарии, выполняет команды, сообщает об ошибках |
| `run_repl()` | интерактивный цикл |
| `main()` | печатает параметры, запускает скрипт и/или интерактивный режим |

## Примеры работы

**Запуск с обоими параметрами** (`scripts/start_ok.txt`):

```
=== Параметры запуска ===
Путь к VFS: vfs\test.zip
Путь к стартовому скрипту: scripts\start_ok.txt
=========================
myvfs> ls
ls: аргументы: []
myvfs> ls -l папка1 папка2
ls: аргументы: ['-l', 'папка1', 'папка2']
myvfs> cd папка1
cd: аргументы: ['папка1']
myvfs> cd ..
cd: аргументы: ['..']
myvfs> exit
Выход из эмулятора
```

**Скрипт с ошибкой** (`scripts/start_error.txt`):

```
myvfs> ls
ls: аргументы: []
myvfs> foo аргумент
foo: команда не найдена
Ошибка в скрипте 'scripts\start_error.txt', строка 3: foo аргумент
myvfs> cd /
cd: аргументы: ['/']
myvfs> exit
Выход из эмулятора
```

**Скрипт не найден:**

```
Ошибка: не удалось открыть скрипт 'scripts\net_takogo.txt': [Errno 2] No such file or directory: 'scripts\\net_takogo.txt'
```

## Скрипты реальной ОС (Windows)

Запускаются из корня проекта, например `scripts\test_all_params.bat`.

| Файл | Что проверяет |
|------|---------------|
| `test_vfs_param.bat` | только параметр `--vfs-path` |
| `test_script_param.bat` | только `--script`: нормальный скрипт, скрипт с ошибкой, несуществующий файл |
| `test_all_params.bat` | запуск без параметров и с обоими параметрами сразу |
